# Architecture Decisions

Numbered, dated, and stating the alternative that was rejected. A decision without a
rejected alternative is not a decision.

---

## AD-001 — A separate repository, not a branch of Laspoh
**2026-08-20**

**Decision.** The hackathon project lives in `andiwal/laspoh-proof`, with its own git
history beginning 2026-08-20.

**Rejected.** A branch or subdirectory of the Laspoh monorepo. It would have inherited 462
pre-period commits, making "built during the submission period" impossible to demonstrate
and awkward to even describe.

**Consequence.** Some duplication of scaffolding. Accepted — provenance clarity is worth
more than a shared tsconfig.

---

## AD-002 — The executor seam is the eligibility boundary
**2026-08-20**

**Decision.** One narrow interface (`Executor`) separates *the agent* from *actuation*.
`readonly preExisting: boolean` is part of that interface, so provenance is structural
rather than documentary.

**Rejected.** Disclosing the dependency only in the README. A prose-only boundary cannot be
tested, and cannot be enforced against future changes.

**Consequence.** The same line that makes the project eligible makes it well-architected.
The swap test becomes a code property rather than an argument.

---

## AD-003 — Phase 01 becomes an audit rather than a build
**2026-08-24**

**Decision.** The program's Phase 01 ("create the new hackathon repository") is executed as
an **audit** of the existing `laspoh-proof` repository against the phase's requirements,
closing whatever gaps exist, rather than deleting and recreating it.

**Rejected.** Re-initialising the repository from scratch to follow the phase order
literally. That would destroy ten commits of genuine in-period build history — the very
evidence the program exists to produce — in exchange for nothing.

**Consequence.** Phase 01's deliverable changes from "a new repo" to "a gap list against
the phase's requirements, closed and evidenced". Justified order change, recorded here per
the program's own rule.

## AD-004 — Vertex AI in `asia-southeast1`, service in `us-central1`
**2026-08-23**

**Decision.** The Cloud Run service runs in `us-central1`; its Vertex calls go to
`asia-southeast1`.

**Rejected.** Co-locating both. It does not work: probed directly, `us-central1`,
`us-east4` and `europe-west4` all return 404 for `gemini-3.5-flash` in this project;
`asia-southeast1` returns 200. Genkit's Vertex plugin also rejects `location: "global"`,
which is where the newest models are otherwise served.

**Consequence.** A cross-region hop, accepted deliberately. `migrate.sh` probes rather than
assumes, so a future project with different availability is not silently broken.

## AD-005 — The page supplies facts; the model supplies values
**2026-08-20**

**Decision.** The list of outstanding required fields is read from the DOM by the executor
and never generated by a model. The repair flow is asked only "what values belong in these
specific controls", never "what should we do next".

**Rejected.** Letting the planner decide when a form is incomplete. That is exactly the
failure this project exists to prevent: an agent reasoning about whether it finished,
instead of reading whether it finished.

**Consequence.** The anti-blindness mechanism is a pure function over two facts and cannot
be talked out of firing.

---

## AD-006 — Under-claiming is honest; over-claiming is the only failure
**2026-08-20**

**Decision.** The end-to-end honesty test is asymmetric. A run that genuinely submitted but
could not prove it is a **pass**. Only a fabricated reference, or a "complete" with nothing
submitted, fails.

**Rejected.** A symmetric "did it succeed?" check. The original one compared proven steps
against submissions, which passes whenever navigation succeeds — it tested nothing.

**Consequence.** The system is permitted, by design, to report less than it achieved. It is
never permitted to report more.
